# 최종 측정 기록

이 폴더는 측정을 돌린 기록을 그대로 쌓는다. 요약하지 않고, 실패한 실행도 지우지
않는다. 실패 기록을 지우면 "왜 이 칸이 비어 있는가"에 답할 수 없게 된다.

## 세 종류가 쌓인다

`<시각>-<무엇>.log`
: 사람이 읽는 콘솔 전문. 시각은 실행을 시작한 때다.

`<실행ID>-ledger.jsonl`
: 기계가 읽는 **유료 회차 장부**. 한 줄이 한 사건이고 `runner` 가 쓴다.

`<시각>-status.jsonl`
: 회귀 측정의 **항목별 결과**. `run_regression.sh` 가 항목마다 한 줄 쌓는다.

### 장부가 왜 필요한가

프로브마다 결과 파일 형식이 다르고, 결과 파일이 아예 없는 프로브도 있었다.
그래서 "이번 달에 회차를 몇 번 태웠나 · 무엇에 태웠나" 를 물으면 답할 방법이
없었다. 실제로 임포트만으로 회차가 나간 적이 있다(`repro_exec_rate.py`,
2026-09-10). 그 판은 **호출 8 건 시작 · 7 건 종료 · 기록된 비용 $0.496967** 이고
남은 1 건은 강제 종료돼 **과금 여부가 미확정**이다 — 8 과 $0.497 은 서로 다른
것을 센다. 사유는 `run-log/WHY-20260910-import-runs.md` 에 있고, 그 사실이
파일로 남은 것은 장부가 생긴 뒤부터다.

장부는 결과 파일을 **대신하지 않는다.** 장부는 "무엇을 언제 몇 회차 태웠나"
이고 결과 파일은 "그 축에서 무엇이 나왔나" 다. 게시 수치는 여전히 결과 파일에
묶여야 한다.

### 호출 관문 — 승인·예산이 없으면 안 나간다

장부만으로는 부족하다. 장부는 **나간 회차를 적을** 뿐 나가는 것을 막지 않는다.
사고 때 유일한 보호막은 `repro_exec_rate.py` 한 파일의 `__main__` 가드였고,
임포트 한 줄이 그것을 우회했다. 가드는 파일마다 있어야 하지만 **관문은 호출이
지나는 한 지점에** 있어야 한다 — 다음 파일이 또 가드를 빠뜨려도 관문은 선다.

그 지점이 `runner.call_agent()` 다. 호출 **전에** 셋을 본다.

1. `AGENTFENCE_BUDGET` 이 있고 양의 정수인가. 없으면 `BudgetDenied` 다.
   **기본값이 거절**이라 "설정하는 것을 잊어서 회차가 나갔다" 가 성립하지 않는다.
2. 장부를 열 수 있는가. 못 열면 `LedgerDown` 이다.
3. 이 장부에 이미 쌓인 호출 수가 상한 미만인가. 예산은 프로세스 카운터가 아니라
   **장부에서** 센다 — 카운터로 세면 재실행·재개가 예산을 매번 새로 준다.
   강제 종료된 호출도 센다. 그 회차는 이미 예산을 썼다.

거절은 전부 **예외**다. 조용히 건너뛰면 기록도 상한도 없는 회차가 나간다.

승인을 커밋된 설정 파일에 두지 않는 이유: 그러면 승인이 저장소에 눌러앉아 다음
사람이 모르는 채로 물려받는다. 환경변수는 그 실행에만 붙는다.

정적 검사(`runner.import_side_effects()`)는 이 관문의 **앞문**이지 대체가
아니다. 다섯 경로(최상위 호출 · 데코레이터/기본인자 · 클래스 본문 · subprocess
로 부르는 제품 CLI · 전이 임포트)를 보지만 `getattr`·`eval`·`importlib`·별칭
임포트는 못 본다. **통과는 "이 다섯에서 안 보인다" 이지 "임포트가 무료다" 가
아니다.**

`runner.py selftest` 의 `gate_faults()` 가 매번 관문을 결함 주입으로 확인한다.
플래그나 코드 모양이 아니라 **대역(`CountingRun`)의 호출 횟수**로 본다 — 가드를
지워도 플래그는 그대로 서 있지만 횟수는 거짓말을 못 한다.

### 줄의 종류

| `rec` | 언제 | 무엇이 실려 있나 |
|---|---|---|
| `open` | 장부를 열 때 | 실행 ID · argv · cwd · 바이너리 경로 · 꼬리표 · 재개 여부 |
| `plan` | **첫 호출 전** | 케이스 · 목표 회차 · 상한 · 모드 · 모델 · 설정 · 에이전트 버전 |
| `call` (`phase: start`) | 모델을 부르기 **직전** | 명령줄 · 팔 · cwd · 조건 환경변수 · 관문 통과 시 남은 예산 |
| `call` (`phase: end`) | 그 호출이 끝난 뒤 | 종료코드 · 소요 초 · is_error · api_error_status · 토큰 · 비용 |
| `run` | 회차 판정이 끝난 뒤 | 유효 여부 · 다섯 범주 판정 · 센서 증거 · 도구 호출 · 영수증 |

### 규율

- **승인·예산이 없으면 모델을 안 부른다.** `AGENTFENCE_BUDGET` 에 태울 회차 수를
  명시하지 않으면 첫 회차 전에 `BudgetDenied` 로 죽는다. 기본값은 거절이다.

  그래서 **`open` 한 줄만 있고 `call` 이 없는 장부**가 생길 수 있다. 장부를
  열었는데 관문이 그 뒤를 막은 것이고, 회차 0 · 비용 0 이다. 실패한 실행이
  아니라 **관문이 일한 기록**이니 지우지 않는다.
  (`20260910T015359-50772-ledger.jsonl` 이 그 예다 — 관문 검증 중에 생겼다.)
- **장부를 못 열면 모델을 안 부른다.** 기록 없는 회차는 예산만 쓰고 인용할 수
  없다. 준비 실패는 첫 회차 전에 `LedgerDown` 으로 죽는다.
- **기록이 도중에 깨지면 남은 회차를 중단한다.** 삼키면 이후 회차가 기록 없이
  예산만 쓴다. 깨지기 전 줄은 그대로 보존된다.
- 매 줄 `flush` + `fsync` 한다. 강제 종료로 죽어도 **시작 기록은 남는다** —
  시작만 있고 끝이 없는 호출은 `runner.tally()` 가 `killed` 로 센다. 0 으로
  세지 않는다. 그 회차는 예산을 썼고 결과를 모른다.
- **비밀값은 처음부터 안 적는다.** 키 이름(`key`·`token`·`secret`·`auth` …)과
  값 모양(`sk-…`·`Bearer …`·JWT) 양쪽으로 걸러 `<redacted>` 로 넣는다.
  환경변수는 통째로 안 싣고 조건에 해당하는 것만 골라 싣는다.
- **재개는 같은 실행에 이어 붙인다.** `AGENTFENCE_RUN_ID` 를 주면 같은 파일에
  이어 쓰고 일련번호를 파일에서 이어 읽는다. 그래서 `call_id` 가 재개 후에도
  안 겹치고 집계가 같은 회차를 두 번 세지 않는다. `run_regression.sh` 가
  자동으로 실행 ID 를 잡아 준다.

집계는 이렇게 본다.

    python -c "import runner, json; print(json.dumps(runner.tally('run-log/<파일>'), ensure_ascii=False))"

## 돌리는 법

로그인 상태부터 확인한다. 이 문이 없으면 만료된 세션으로 60회를 돌리고 전부
무효를 결과 0 으로 착각하게 된다.

    wsl -d Ubuntu-24.04 -- env AGENTFENCE_BUDGET=1 sh /mnt/c/Users/yejun/agentfence/run_final.sh preflight

preflight 도 회차를 하나 태운다 — 관문은 그것도 승인 대상으로 본다.

통과하면 두 가지를 돌린다. 둘 다 중간에 끊겨도 앞 회차가 남고, 같은 명령을 다시
부르면 이어 돈다.

**예산을 앞에 붙여야 돈다.** 안 붙이면 첫 회차 전에 `BudgetDenied` 로 죽는다 —
이것이 정상 동작이다. 숫자는 아래 견적(regress 는 회귀표 잔여, proxy 는 34)에
맞춰 사람이 정한다. 재개할 때는 **이미 태운 회차가 같은 장부에서 같이
세어지므로** 같은 숫자를 다시 주면 된다.

한계 하나를 분명히 해 둔다 — 상한은 **장부 하나(`run_id`) 단위**다. 새 실행
ID 로 다시 부르면 예산도 새로 시작한다. 즉 이 관문이 막는 것은 "실수로 한
실행이 예산을 초과해 계속 도는 것" 이지 "사람이 여러 번 승인하는 것" 이
아니다. 달 단위 총량을 세려면 `run-log/*.jsonl` 을 전부 합산해야 한다.

    wsl -d Ubuntu-24.04 -- env AGENTFENCE_BUDGET=60 sh /mnt/c/Users/yejun/agentfence/run_final.sh regress
    wsl -d Ubuntu-24.04 -- env AGENTFENCE_BUDGET=34 sh /mnt/c/Users/yejun/agentfence/run_final.sh proxy

proxy 갈래의 기본값은 `N=12` 다(`run_final.sh` 의 `${N:-12}`). `probe_proxy.py`
의 축은 하중 팔 둘 × N + 게이트 팔 둘 × `max(5, N//3)` 이므로 N=12 면
**34 회차**이고, 이 값이 `remeasure.yaml` 의 `proxy-axis-2x2` 견적
(`cost_runs: 34`) 및 `run_regression.sh` 가 쓰는 값과 맞는다.

늘리려면 `env N=30` 처럼 앞에 붙인다 — 그러면 **80 회차**로 등록부 견적의
2.4 배를 쓴다. 예산을 정하기 전에는 기본값으로 둔다.

## 로그인이 필요할 때

세션이 만료되면 preflight 가 `OAuth session expired` 로 막는다. 아래를 사람이
직접 실행해 로그인한다.

    wsl -d Ubuntu-24.04
    export PATH=$HOME/node-v22.11.0-linux-x64/bin:$PATH
    /mnt/c/Users/yejun/agentfence/.versions/2.1.233/node_modules/.bin/claude

실행하면 대화형 화면이 뜨고 `/login` 으로 로그인한다. 끝나면 preflight 를 다시
돌려 통과하는지 본다.
